ITCYBER RAILWAY HEALTHCHECK FIX - v4.0.1
=============================================

WHAT WAS FIXED
--------------
1. Removed the Railway startCommand that used `$PORT` without a shell.
   On Dockerfile/image deployments Railway start-command overrides run in exec
   form, so `$PORT` is not expanded unless a shell is used. That can stop the
   Python server before the healthcheck ever becomes healthy.
2. Added a tiny public GET /health endpoint that always returns HTTP 200 while
   the API process is alive.
3. Kept GET /api/health for full diagnostics.
4. Added HEAD support for /, /health, /ready and /api/health.
5. Incomplete admin bootstrap variables no longer crash the API at startup.
6. Added a root Dockerfile + root railway.toml so Railway can deploy the backend
   even when the monorepo Root Directory is left blank.
7. Fixed Vercel/Railway CORS credentials and cross-site session cookie handling.

RECOMMENDED RAILWAY SETUP (EASIEST)
------------------------------------
1. Push THIS entire folder to the existing GitHub repository.
2. Railway -> Backend service -> Settings -> Source: choose that repository.
3. Root Directory: CLEAR IT / leave it blank.
   The new root Dockerfile intentionally deploys the backend folder.
4. Build Command: clear/blank.
5. Start Command: clear/blank. Do NOT type a custom start command.
6. Healthcheck Path: /health
7. Healthcheck Timeout: 300 seconds.
8. Do NOT create your own PORT variable. Railway injects PORT automatically.
9. Variables (replace values):
     ITCYBER_ALLOWED_ORIGINS=https://YOUR-FRONTEND.vercel.app
     ITCYBER_BOOTSTRAP_ADMIN_NAME=Admin
     ITCYBER_BOOTSTRAP_ADMIN_EMAIL=admin@example.com
     ITCYBER_BOOTSTRAP_ADMIN_PASSWORD=USE-A-STRONG-PASSWORD123
10. Redeploy.

ALTERNATIVE IF YOU WANT ROOT DIRECTORY /backend
-----------------------------------------------
- Root Directory: /backend
- Config File Path: /backend/railway.toml
- Build Command: blank
- Start Command: blank
- Healthcheck Path: /health

SUCCESS CHECK
-------------
Deployment logs should contain:
  ITCYBER scraper API running at http://0.0.0.0:<RailwayPort>/

After Railway creates a public domain, open:
  https://YOUR-DOMAIN.up.railway.app/health
Expected:
  {"ok": true, "status": "healthy"}

Then open:
  https://YOUR-DOMAIN.up.railway.app/api/health
Expected: JSON containing "ok": true.

FRONTEND AFTER BACKEND IS HEALTHY
---------------------------------
Edit frontend/config.js and replace:
  https://YOUR-RAILWAY-SERVICE.up.railway.app
with your real Railway HTTPS domain (no trailing slash), commit, and redeploy
Vercel.
